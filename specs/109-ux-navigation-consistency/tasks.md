# Tasks: Navigation, Scope Filters and Cross-Surface UX Consistency

**Input**: [spec.md](spec.md) · [plan.md](plan.md) (PR table, merge order) · [research.md](research.md) D1–D28 · [data-model.md](data-model.md) · [contracts/](contracts/) · [quickstart.md](quickstart.md)
**Organization**: one phase per PR. Phase numbers are for reference only (109-d and 109-e follow 109-k, and 109-g and 109-h follow 109-d, although some of their phases come first); the binding order is the Dependencies graph at the end (merge waves `(a ∥ b ∥ c) → (f ∥ j ∥ k) → (d ∥ e) → (g ∥ h) → i → m`, with `l` after Spec 108-f/i/j). Inside each phase the order is: failing tests first → implementation → verification (common gates + live recipe from quickstart §3) → zcode review.
**Story labels**: **US1** needs attention · **US2** informed review · **US3** clients hub · **US4** server status/next action · **US5** catalog/add server · **US6** navigation/header/filters · **US7** onboarding.

**Format**: `- [ ] [ID] [P?] [Story] Description with file path`. `[P]` = can run in parallel within the phase (different files, no dependency).

**Common verification (every PR)**: quickstart §1 gates + the PR's live recipe (quickstart §3) on an isolated instance (quickstart §2) + zcode review, ≤ 10 rounds (codex only for 109-f).
