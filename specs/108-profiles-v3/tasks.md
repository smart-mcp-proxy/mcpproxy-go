# Tasks: Profiles v3 — Scoped Profiles, Client Binding and Scope-Aware Observability

**Input**: [spec.md](spec.md) · [plan.md](plan.md) (PR table, merge order) · [research.md](research.md) D1–D30 · Spec 109 (ownership split; cross-spec edges below) · [data-model.md](data-model.md) · [contracts/](contracts/) · [quickstart.md](quickstart.md)
**Organization**: one phase per PR in merge order `a → (b ∥ c) → d → e → f → (g ∥ h ∥ i ∥ k) → j → l`, plus the cross-spec edges a ← 109-a (`contracts.AnnotationTier`, research D30), f ← 109-h, i ← 109-h + 109-i + 109-k, j ← 109-k, k ← 109-h + 109-i + 109-k (Spec 109 owns `useScopeQuery`, the link map, `ScopeFilter`, the Clients page shell and `GET /clients`/`client list|show` presence, sidebar/header layout). Inside each phase: failing tests first → implementation → verification (test plan + live recipe from quickstart §3) → zcode review. Story labels: **US1** read-only enforcement · **US2** client binding · **US3** filters/deep links/explainer · **US4** profile management · **US5** anonymous confinement.

**Format**: `- [ ] [ID] [P?] [Story] Description with file path`. `[P]` = parallelisable within the phase (different files, no dependency).

**Common verification (every PR)**: quickstart §1 gates + the PR's live recipe (quickstart §3) on an isolated instance (quickstart §2) + zcode review ≤ 10 rounds (codex only for 108-c, 108-d).
