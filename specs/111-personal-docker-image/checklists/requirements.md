## Notes

Validation run on 2026-09-26 (one pass). Items left unchecked, with the reason:

- **No implementation details / not for non-technical stakeholders / no leakage.** The product being specified is a container image, so its user-visible contract is technical by nature: image names and tags, the `/data` path, UID 65532, `docker run` usage, probe paths and exit codes are what users type and configure. These are kept as contract, in line with house style (Spec 109 names endpoints and files). Deliberately kept out of spec.md: Dockerfile contents, base-image digests, the NodeSource vs multi-stage choice, ldflag names, workflow YAML and job names; they live in research.md (D2, D5–D8, D14). Accepted, not a defect.
- **Success criteria technology-agnostic.** SC-002 (image size), SC-004 (named volume vs bind mount), SC-006 (per-architecture publishing) and SC-007 (Server image's tags/entrypoint/user/state-path byte-for-byte unchanged) name container concepts because they are the product's measurable properties. SC-001, SC-003, SC-005, SC-008 and SC-009 are user-facing. Accepted.
- **NEEDS CLARIFICATION markers.** Resolved 2026-09-26 via `/speckit.clarify` (spec.md "## Clarifications", Session 2026-09-26). Both checkboxes above now check:
  - FR-026: resolved as document-only (research D11 option A). No container-friendly OAuth sign-in flow ships in this spec; the docs name host networking and desktop sign-in plus a manual OAuth token-state copy (the data directory's database, not `mcp_config.json`) as workarounds, and a paste-the-redirect-URL flow is a follow-up spec. US5 scenario 4 is now a testable scenario (the UI/CLI must show the limitation and both workarounds), not a placeholder.
  - FR-036: resolved as **B**, scoped to full/slim only (never the Server image) — the Personal full/slim images default `require_mcp_auth` to `true`; the desktop and Server-image defaults are unchanged (`false`). Applied via `DefaultConfig()` reading a **new, dedicated build-time boolean** stamped only by the full/slim Dockerfiles (both the official CI-published build and the FR-041 local build target), deliberately *not* the CI-only `image_variant` marker (research D12; round 5/6 review found reusing the marker would leave FR-041 local builds with the default unset and would incorrectly flip the Server image too). This is the *product-wide* image default for operators who write their own config; FR-035 separately still requires the flagship LAN example to set the authentication explicitly in its own config as belt-and-suspenders (Edge Cases, "`/mcp` published to the LAN").
